# 原始 V1 与当前组件：模式／旋转同板对照（2026-11-03）

原始 V1 从历史提交 `41b0c9b9b6f72735cfa8878c159b1c25795b48e6` 导出，当前版基于 `8c69118a6182a83a22450710b06bc5a4563030b9`，含一次未提交的 SPI 平台写法调整；生产源码 diff SHA256 为 `cad4ff898f3e9229ec9b08507972ce5d82d3960f47a7dab510bdf1cf3685750b`。ESP-IDF 使用 `7b9cc1ac79f8` 工作区并含只读 LCD 能力查询补丁，非未修改的上游 SDK。旧版仅供测试，不并入生产。

## 功能覆盖

| 实板 | 原始 V1 | 当前组件 |
| --- | --- | --- |
| P4 MIPI，1024×600 | 25 通过，3 不支持 | 28 通过 |
| S3 RGB bounce，480×480 | 25 通过，3 不支持 | 28 通过 |
| S31 QSPI，480×480 | 23 通过，9 不支持 | 32 通过 |

两版合计 161 项通过，15 项按原始 V1 的创建限制返回 `ESP_ERR_NOT_SUPPORTED`；无其他拒绝或像素失败。P4／S3 的三项是 DIRECT 非 0°；S31 的九项是三组无 TE 的 GRAM 在非 0°。这些是**创建时**设置角度的结果；运行时旋转是另一条接口，P4 跨轴旋转已知问题仍在，见 [专项结果](MODE_ROTATION_RESULTS_20261103.md)。

同一测试源、同一块板及 SDK，每配置创建 presenter、绘制 12 帧全屏彩条和移动方块，逐像素核对提交数据、窗口、完成状态。RGB565、16 行 tile；P4 CPU/PSRAM 为 400/200 MHz，S3 为 240/80 MHz，S31 为 320/200 MHz。S31 的 TE 每帧一次 480×480 物理整屏提交，未发送不对齐的局部 TE 窗口；其 GRAM 用全宽 band。T1/T2 表示 tile 数，C1/C2 表示 TE compose 数。P4/S3 驱动创建了 3 块 FB，NONE 使用其中 1 块，双缓冲使用 2 块；未验证驱动自身只创建 1 块 FB。AUTO 是自动选择的配置。

实际测试是单次运行。像素检查发生在应用提交的内存侧，非面板光学采样；并未证明 TE 无撕裂。用户反馈 P4 和 S31 目前画面正常；反馈到达时本轮测试和恢复已结束，无法确认覆盖了哪些模式或角度。S31 重复创建仍出现 GPIO ISR service 已安装及 IO 回调覆盖日志，S3 有 GPIO3 占用 warning。原始 V1 不支持配置的创建错误日志也保留。

## 对照口径：逐帧操作耗时倒数

下表每格为 **V1 → 当前**，单位为次/秒，按 `12,000,000 / total_frame_us` 折算。计时包含每帧 begin、应用生成图案、提交、commit、quiesce，以及 GRAM 抓取包装的工作；不含逐像素核对和每帧 60 ms 人为间隔。该程序每帧串行等待，不能反映多帧流水线吞吐。**这不是 LVGL benchmark，也不是屏幕实测显示帧率。**

尤其需要注意 FB 的完成语义差异：原始 V1 在 FB 关闭 transfer tracking，且 `quiesce_present_tail = 1`，允许 present 完成水位落后一帧；当前门面的 quiesce 等待核心 terminal receipt，而 FB backend 在收到 `SCANOUT_CONFIRMED` 后才将对应帧置 terminal。因而表中 FB 的两次调用不保证在相同物理显示边界返回，较低数值不能直接认作实际使用性能降低。两个条件是解释差异的明确线索，具体占比仍需分段计时验证。 该等待差异在较短超时下可能改变旧调用的返回结果，是否属于需要修复的兼容行为仍需专项验证；这次不声称两版 quiesce 完全等价。

## LVGL 官方 benchmark：更接近界面使用

[此前同板 0° LVGL 9.5 官方 benchmark](VALIDATION.md)每版运行一次、16 个场景，使用 RGB565、2×50 行 tile，33 ms 刷新周期。P4／S3 是三 FB PARTIAL，S31 是无 TE 的 GRAM：

| 板／显示 | V1 FPS | 当前 FPS | V1／当前 render ms | V1／当前 flush ms | V1／当前 LVGL CPU |
| --- | ---: | ---: | ---: | ---: | ---: |
| P4 MIPI | 27 | 27 | 15 / 16 | 0 / 4 | 47% / 61% |
| S3 RGB bounce | 19 | 17 | 52 / 52 | 4 / 6 | 86% / 89% |
| S31 QSPI，TE 关闭 | 25 | 25 | 20 / 22 | 5 / 5 | 62% / 65% |

不能把上面的 0° LVGL 数据推广到所有角度或 TE；也不能把合成图案的操作耗时倒数当成 LVGL FPS。这次官方 benchmark 中 P4、S31 的汇总 FPS 表面持平，S3 当前版低 2 FPS；33 ms 刷新周期会掩盖轻负载场景的性能差异。例如 P4 的 Multiple RGB images 两版均为 30 FPS，但 flush 为 1 → 23 ms、LVGL CPU 指标为 19% → 87%；S3 的 Multiple rectangles 为 29 → 23 FPS、flush 为 4 → 8 ms。LVGL CPU 指标并非逐核占用率，单次结果尚需重复验证。这些现象说明性能回退需要进一步定位，不能只凭汇总 FPS 宣称 P4 没有回退。
