# S31 取指停顿与单tile派发对照

本轮只定位S31 Korvo 800×480的DOUBLE_PARTIAL，0°/90°，单输入tile，双方分别80000B/48000B。两边均为10行RGB bounce，每块16000B、共两块，板级代码和IDF相同。XIP开／关各跑：present每角度worker→调用线程→调用线程→worker；adapter每角度重复两次。共24项、384个完整场景。每组两次；小幅差异不作为统计显著结论。CPU配置320MHz、Flash 80MHz DIO、PSRAM 200MHz，I-cache 16KiB、D-cache 64KiB，双方一致。

同一份present固件在用例边界切换执行方式，保留pixel worker、后台sender及其资源；只在隔离副本的pixel_submit选择现有同步执行分支。ticket、完成通知、回收与scanout退役契约保持。这里的调用线程可能是UI或后台提交者，不把它误写为所有复制都在UI执行。仓库生产源码、IDF未修改。adapter保持logical-50隔离分配overlay。

计数是两个I-bus的整机窗口总和，不是仅LVGL函数；按非空render次数归一化。每场景预热至少1秒，每250ms采集并清零，饱和项拒收，关闭显示前停止计数，关闭后再打印。line_fills是真实填充次数；stall_events在缺失等待期间重复累加，只作相对指标，不换算为CPU周期或毫秒。request conflicts表示请求者仲裁冲突，不是cache set映射冲突；零值不能排除缓存行被挤出。

## 结果

两边139个LVGL源码对象的重定位前.text机器码一致，最终链接地址不同；这排除了本轮LVGL源码对象编译差异，尚不能证明具体缓存映射冲突。
XIP off、0°全屏文字：worker/adapter停顿比3.24 = 填充次数比2.70 × 每次填充停顿比1.20。
XIP off、90°全屏文字：worker/adapter停顿比2.64 = 填充次数比2.31 × 每次填充停顿比1.14。
XIP off、0°绕过pixel派发：有效绘制6.90→6.90/s，停顿38.12→34.91M/帧。
XIP off、90°绕过pixel派发：有效绘制5.30→5.16/s，停顿42.82→41.31M/帧。
0°直接执行仍有2.66倍adapter的填充；本轮未通过绕过pixel worker追回文字吞吐。这个对照不支持把像素worker派发当成该场景的主要根因。
填充次数偏高已经测到；具体是哪些热函数／代码布局／执行交错造成，尚未独立定位。应继续定位热代码驻留，不能仅凭本轮将生产路径整体改成同步。
XIP on、0°：worker/adapter填充比仍为3.96，但停顿/填充为220.70/217.92。XIP改善了等待代价，没有让本组填充次数收敛。

探针会改变链接布局与调度，本轮只在同版内对照，不把新旧停顿数差异当作严格因果。具体热函数／cache set冲突尚不能由这些计数独立定位；不把request-conflicts当作set-conflicts。两实现不同链接布局会影响缓存行为。worker/inline两组位于同一固件，只改变像素请求是否派发给worker，后台sender仍保留，不能将结果外推为所有任务交接都无影响。

公开数据的完整16场景成绩与诊断结果分开，本轮不覆盖原矩阵。原始CPU100%无效，CPU成本使用FreeRTOS任务运行时间。文字场景每帧固定384000像素，0°10次flush、90°16次flush，优先用于分解；其他动画场景应结合像素/帧判断，不能把文字结论外推全部PARTIAL。两次重复只给出范围，不宣称小幅变化具有显著性。

[链接布局定点实验](layout.html)：额外 8 次 18 秒全屏文字运行，只改变 present 两个链接符号的提前提取，包含前后基线和 adapter 对照，保持单 tile 和双方 10 行 bounce；不替换正式矩阵。

[继续定位的完整证据](root-cause.html)：额外30项18秒定点运行，24字节平移、PC热点、全局32B对齐反证及单函数字体解包IRAM验证；没有覆盖正式分数。最终原固件整片恢复校验通过。
