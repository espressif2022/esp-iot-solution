# V1／V2 双 FB 吞吐与扫描边界复测（2026-11-03）

最新 S3 双 PARTIAL／DIRECT 已在指定负载下恢复到约 60 次提交／秒，见 [热路径放置修复与原版驱动 A/B](FB_IRAM_RESULTS_20261103.md)。以下为历史基线。

## 结论

后续已实现不新增驱动退休接口的提交门控／ISR join 修复，结果见 [FB_ISR_JOIN_RESULTS_20261103.md](FB_ISR_JOIN_RESULTS_20261103.md)。以下保留修复前的双回调基线与原始诊断，不代表当前代码仍固定等待两次回调。

在相同的合成绘制循环下，最终 V2 仍比原始 V1 慢；实板诊断显示本轮两块板的 V2 每次切换都等待两次已布防的 FB 完成回调，旧 FB 的最后读取结束标记到 V2 释放标记相差约 16.6 ms。P4 双 PARTIAL 约 30 次／秒，S3 双 PARTIAL 约 20 次／秒。两次回调形成的保守退休节拍是主要限制之一；S3 的 tile 获取等待也占据约 12.6 ms／帧，不能把所有差距都归于某一个等待点。

这不是 LVGL 官方 benchmark，也不是光学帧率。V1 和 V2 的完成水位与退休语义不同；本表表示指定生产者在其各自的完成条件下的吞吐。**本轮没有把两次回调改为一次，也没有声称性能问题已经修复。**

## 实板驱动事件

诊断固件在隔离的 V1、V2 和 IDF 驱动副本中插桩；每例 4 帧预热 + 30 帧，环形记录容量 4096，输出均无溢出。记录提交、选择 FB、驱动读取开始／结束、回调、V2 布防／确认、释放和生产者获写权限。S3 bounce EOF 仅每 8 次采样一次；完整 FB 读开始／结束事件未抽样。计时均为软件标记之间的时间，不是外部总线探针。

| 板卡／双 FB | 版本 | 最后读取结束标记 → 释放，平均 | 条件与异常 |
| --- | --- | ---: | --- |
| P4 PARTIAL | V1 | 7.1 µs，33 笔 | 首帧授予当前选中 FB 写权限；首次释放 FB 未观察到先前读结束 |
| P4 DIRECT | V1 | 7.0 µs，34 笔 | 本次没有记录到选中／读取中 FB 被交回 |
| P4 PARTIAL／DIRECT | V2 | 16.58／16.59 ms，各 34 笔 | 每次确认均为两次已布防回调，未观察到选中／读取中 FB 被交回 |
| S3 PARTIAL | V1 | 9.1 µs，33 笔 | 首帧授予当前选中 FB 写权限；首次释放 FB 未观察到先前读结束 |
| S3 DIRECT | V1 | 9.1 µs，34 笔 | 2 次驱动 restart，原因标记为 EOF 数不足 |
| S3 PARTIAL | V2 | 16.60 ms，34 笔 | 每次确认均为两次已布防回调；2 次 EOF 数不足的 restart |
| S3 DIRECT | V2 | 16.62 ms，34 笔 | 每次确认均为两次已布防回调，本次无 restart |

V2 每例有 34 笔应用帧释放、35 次切换确认：额外一笔是初始化 scanout，不是凭此判断丢帧。V1 PARTIAL 在 P4 和 S3 各一次首帧出现当前选中／读取中的 FB 已授予写权限；插桩标记的是租约授予时刻，并非逐字节写入探测，不能由此单独断言发生了可见撕裂。第一次释放的另一 FB 没有先前读取标记，也不能纳入平均值。

S3 两组带插桩测试各出现两次 restart，原因位 `0x4` 对应驱动观察到 bounce EOF 数少于预期。记录器本身占用中断时间，可能扰动此场景；仅凭这些记录无法判断原始固件是否也有同样问题，所以这两组不是完整的缓冲安全通过证据。P4 的 DMA 读取标记由驱动 ISR 记录；S3 的结束标记位于最后一次 bounce 拷贝之后。指针匹配的 SELECT 只能作为相关性证据，软件 SUBMIT 标记和驱动实际选中之间可能有交错，无法证明每个提交代次均被显示。

## 原因和安全边界

当前 [present_lcd_scanout.c](../src/platform/present_lcd_scanout.c) 在正常多缓冲配置中计数两次 `frame_buf_complete` 后才发出 `SCANOUT_CONFIRMED`；[present_backend_fb.c](../src/backend/present_backend_fb.c) 收到确认后退休旧扫描 FB。本轮轨迹与这一策略吻合，约一个显示周期的额外保留直接约束双 FB 周转。

但在普通 IDF 回调中，事件不携带与提交原子关联的 FB／代次。提交与 ISR 读取选中缓冲、回调之间可能交错；地址重复使用还存在 ABA。仅凭“正常轨迹第一次回调看起来够早”改成一次等待，不能保证旧缓冲不再被硬件读取。V1 的首帧结果也说明，吞吐高不能自动证明初始化所有权正确。

后续应先设计驱动侧能标识**实际选择的 FB 和对应切换代次**的完成证据，明确 MIPI 与 RGB bounce 的触发点及 reset／restart 语义，再在有该能力的路径使用单边界；旧驱动继续使用当前安全回退。实现前需要 Host 覆盖过期或早到回调、重排、同地址轮转、失败及停止，再做两板低扰动、压力和重启轨迹。S3 EOF 异常须先用低开销独立计数复查。实现并验证之后再重跑相同测试和 LVGL 官方 benchmark。
