# V1／当前组件分段性能分析与修复（2026-11-03）

## 结论和范围

**后续复测：** P4／S3 在两项修复同时存在的最终代码上已重新测试，并补充真实驱动边界轨迹；最新数据、异常和限制见 [FB_TIMING_V1_V2_20261103.md](FB_TIMING_V1_V2_20261103.md)。

- 异步像素拷贝线程原来固定优先级 5；本测试的生产者优先级是 6。线程采用首次成功提交的生产者优先级后，S31 的 TE 双 compose、90° 合成吞吐从 29.0 恢复至 39.4 帧／秒，与 V1 的 39.5 接近。修复不改 PPA 字节序、缓存维护、缓冲所有权或 TE 准入。
- DIRECT 帧明确请求整屏重绘时，不再把前一帧预填到新缓冲，实际覆盖不足时仍拒绝封帧；局部 DIRECT 更新仍先保留所需旧像素。P4／S3 双缓冲 DIRECT 合成吞吐分别由 15.1→20.1、20.1→30.0 帧／秒。
- P4／S3 的 FB 其余主要差距没有修复：当前仍保守等待两次驱动完成边界；不能将一次 callback 当成旧 FB 已安全退休。S3 的 tile 等待也值得在最终版上重新分段测量。

这些是**合成帧循环吞吐**，不是屏幕光学刷新率，也不是 LVGL 官方 benchmark。V1／当前版完成水位和退休语义不同，计入各自最后一次 drain；直接比较数值时要保留这个限制。此前 LVGL 9.5 官方 benchmark 见 [VALIDATION.md](VALIDATION.md)，本轮没有重跑 LVGL benchmark，因此不推导修复后的官方 FPS。

## 条件

P4/S3 的 DIRECT 回归还覆盖实际覆盖不完整、随后补足、同步／异步拷贝、以及局部更新继承旧图像。S31 的最终版额外让创建发生在优先级 3、实际生产者在优先级 6，验证继承自提交者而不是创建者；日志有 `PRIORITY_TEST`。新规则只在首次成功的异步提交时决定，后续生产者交接不自动调整；生产者优先级改变后的调度影响需要独立评估。

P4/S3 性能修复轮临时源含一个“驱动提供 selected FB 时才走”的诊断分支，测试 IDF 没有定义对应能力宏，实际执行仍为双边界回退；该诊断分支未合入生产代码。对应源差异保存在证据目录。P4/S3 性能修复轮的测试二进制被后续离线编译覆盖，未归档；不能把后续二进制哈希冒充当时运行文件。S31 最终固件以及初始三板 V1／当前测试固件的 SHA256 见证据清单。

## 后续安全边界

1. FB 双边界不可直接删减。要恢复 P4／S3 流水线，需要驱动提供能够区分每一次切换的退休证据：提交代次与具体 FB 必须原子关联，事件必须指明实际选中的代次；还需覆盖早到、过期回调、同一地址再次轮转和序号耗尽。没有证据的旧驱动继续走双边界。
2. 在 Host 中注入上述事件乱序，再用 RGB bounce EOF／VSYNC 和 MIPI DMA 中断环形轨迹验证“旧 FB 最后一次读取早于交回绘制”；同时检查压力和 restart。不要把画面正常等同于无撕裂或缓冲安全。
3. 合成矩阵收敛后，重跑同配置的 LVGL 官方 benchmark；尤其测 S3 的 `begin/acquire`、拷贝、修补及锁等待。P4/S3 两项修复的最终叠加效果已上板复测，见后续复测报告。

Host + LVGL 35/35，ASan/UBSan 35/35；运行时设置 `ASAN_OPTIONS=detect_leaks=0`，本轮**未验证泄漏检测**。最终源码 P4、S3、S31 均在带只读能力查询补丁的隔离 IDF 上离线构建成功。无 TSan、长期竞态穷举、跨 IDF 版本或光学撕裂验证。
